Posicionamento

Do "consulta de CNPJ genérica" para uma plataforma de inteligência temporal sobre empresas brasileiras.

O protótipo atual é tecnicamente bom mas comunica um SaaS qualquer. O Pythagoras tem um diferencial real — o histórico de presença e qualificação de sócios mês a mês, que o CNPJá não tem. Esta direção pivota a UI para tornar isso o protagonista, tira o que é decorativo, e veste a marca de corporativo institucional.

A.01 · Diagnóstico

O que muda na história que a UI conta

A interface hoje é um cartão de visitas detalhado da empresa. A v2 entrega o mesmo cartão, mas com um eixo do tempo embutido em todo lugar — porque é isso que o backend está construindo.

v0.1 — hoje

Consulta de CNPJ com extras genéricos

  • Sócios listados em uma única tabela, todos iguais
  • Timeline de eventos com "diff de capital social" (não existe no backend)
  • Mapa com lat/lng inventados
  • Visual warm + teal, parece um app de produtividade
  • Listas salvas / favoritos como decoração
  • Sem indicar quando a base foi vista pela última vez
v2 — direção

Inteligência cadastral com presença temporal

  • Sócios Ativos e Ex-Sócios em blocos separados
  • Cada sócio com histórico de qualificações ("foi Sócio → virou Administrador em mai/26")
  • Situação especial (Recuperação Judicial, Falência) tratada com peso
  • Visual navy institucional, monoespaçada para números
  • Sem favoritos / listas / mapa — só o que o backend entrega
  • Indicador permanente: "Base: 04/2026 · Visto pela 1ª vez: 03/2014"
A.02 · Identidade

Paleta corporativa — navy como base, azul como ação

Seis tokens. Navy puxa para o institucional; o azul de ação fica reservado para CTAs e elementos que pedem clique. Os neutros são frios (slate), não quentes — combina com dados, planilha, relatório.

B.01 · Remoções

O que sai do protótipo atual

Tudo que é feature decorativa sem suporte do backend, ou que distrai do diferencial. Volta depois se fizer sentido — agora atrapalha.

B.01.1
Timeline de eventos cadastrais com diffs
A RF não fornece diff de mudanças — está explícito no README do projeto. A timeline atual com "R$ 14,5M → 28,5M" é inventada. app.jsx · sections.timeline
Remover
B.01.2
Mapa com pin e coordenadas
O backend não armazena lat/lng. Mostrar pin no mapa é decorativo e sugere precisão que não existe. Endereço continua, sem mapa. styles.css · .map
Remover
B.01.3
Listas salvas / Fornecedores Tier 1
Não é prioridade da Fase 1 do projeto. Sidebar fica enxuta com nav + buscas recentes apenas. Volta quando houver demanda real. app.jsx · Sidebar
Remover
B.01.4
Risk signals genéricos (4 itens fixos)
Os sinais atuais são placeholder — "ativa há 11 anos", "sem pendências". Sem regras de cálculo definidas, vira decoração. Substituído por indicadores temporais factuais. app.jsx · sections.sinais
Remover
B.01.5
Tweak de matiz de accent (slider 0-360°)
Decisão de identidade não fica em slider de usuário. A paleta é navy + azul, fim. app.jsx · TWEAK_DEFAULTS.accentHue
Remover
B.01.6
Modo escuro
Plataforma corporativa B2B raramente usa dark mode em produção, e dobra a superfície de teste. Foco em uma versão light bem feita. styles.css · [data-theme="dark"]
Adiar
B.01.7
Layout em abas (toggle single/tabs)
Mantém só "página única". Tab navigation em página de detalhe esconde informação — em due diligence o usuário quer scroll. app.jsx · TWEAK_DEFAULTS.layout
Remover
B.01.8
Tweak de densidade (compact / cozy / spacious)
Escolher UMA densidade certa. Densidade compacta vira o default — é uma ferramenta de dados, não um blog. styles.css · [data-density="..."]
Remover
B.02 · Adições

O que entra — tudo lastreado no backend real

Cada item abaixo já existe no schema da base (Empresa, Estabelecimento, Sócios, Simples) ou é trivialmente derivável dos campos dt_primeira_carga / dt_ultima_atualizacao. Sem invenção.

B.02.1
Seção "Ex-Sócios" separada de "Sócios Ativos"
O diferencial #1 do projeto. Sócios com dt_ultima_atualizacao menor que o mês mais recente entram aqui, com a data em que foram vistos pela última vez. backend · socios.dt_ultima_atualizacao
Adicionar
B.02.2
Histórico de qualificações por sócio
Como a chave natural inclui cd_qualificacaosocio, mudanças de papel geram múltiplos registros. Cada sócio mostra qualificação atual + anteriores ("Sócio até abr/26 → Administrador desde mai/26"). README · regras de negócio
Adicionar
B.02.3
Situação especial em destaque (Recup. Judicial, Falência)
Texto livre da RF, mas quando preenchido, é o sinal mais importante da empresa. Vira faixa de alerta no topo do card. backend · estabelecimento.nm_situacaoespecial
Adicionar
B.02.4
Indicadores temporais persistentes
No header de cada empresa: "Vista pela 1ª vez em mar/2014 · Última atualização da base: abr/2026". Define o tom do produto inteiro. backend · empresa.dt_primeira_carga
Adicionar
B.02.5
Motivo da situação cadastral
Quando empresa está Baixada/Suspensa, mostrar o motivo da tabela de domínio Motivos. Hoje só aparece "Baixada" — agora "Baixada · Encerramento por extinção". backend · estabelecimento.cd_motivosituacaocadastral
Adicionar
B.02.6
Faixa etária dos sócios PF
Coluna discreta na tabela de sócios — útil em due diligence para identificar sócio idoso/herdeiro. backend · socios.cd_faixaetaria
Adicionar
B.02.7
Aviso "Matriz baixada, filial ativa"
Caso conhecido na base (6.648 empresas em 04/2026). Em vez de mostrar como contradição silenciosa, banner informativo explicando a situação. README · exceções
Adicionar
B.02.8
Resultado de Sócio: empresas atuais × empresas passadas
Mesma lógica dos sócios — quando busca por CPF, separar empresas onde a pessoa ainda é sócia das empresas onde foi, com período. backend · socios join empresa
Adicionar

D.01 · Roadmap visual

Reservar o espaço da rede de relacionamentos

O próximo grande diferencial — grafo de sócios e empresas — não precisa ser construído agora, mas a arquitetura de informação já deve antecipar. Um botão "Ver rede" ghost no header, desativado, comunica que está vindo.

v3 · Próximo grande passo

Rede de sócios e empresas

Dado um CNPJ ou CPF, mostrar visualmente as conexões 2º grau — sócios em comum, fundos compartilhados, holdings. O que uma tabela esconde, o grafo expõe.

  • Nodes em Navy (empresas) e Blue (pessoas)
  • Edges com peso pelo tipo de relação
  • Filtros: só ativos / incluir ex-sócios
  • Toggle Tabela ↔ Grafo
